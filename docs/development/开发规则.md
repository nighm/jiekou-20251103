## 🎯 核心规则

### 规则1：全项目同步规则（CRITICAL）

**规则内容**：
> **任何更新类、配置、关键信息时，必须全项目同步更新**

**适用范围**：
- 配置文件路径变更
- 服务器信息变更（IP、用户名、密码）
- 命令路径变更（如JMeter路径）
- 默认值变更
- 功能接口变更

**同步范围**：
1. ✅ **代码文件** (src/)
   - 所有相关的Python模块
   - 配置文件 (YAML)
   - 测试代码 (tests/)

2. ✅ **文档文件** (docs/)
   - 需求文档 (requirements/)
   - API规范 (api-specs/)
   - 实现文档 (implementation/)
   - 测试文档 (testing/)
   - README文档

3. ✅ **脚本文件**
   - 批处理脚本 (.bat)
   - Shell脚本 (.sh)
   - 测试脚本

4. ✅ **配置文件**
   - pyproject.toml
   - INSTALL.md
   - README.md

**检查清单**：
- [ ] 搜索所有相关文件中的旧值
- [ ] 更新所有代码文件
- [ ] 更新所有文档文件
- [ ] 更新所有脚本文件
- [ ] 验证所有引用都已更新
- [ ] 运行测试确保没有遗漏

**执行命令**（示例）：
```bat
:: Windows 推荐使用 findstr /s /n
findstr /s /n /c:"旧值" src\*.py docs\*.md tests\*.py *.bat *.sh
findstr /s /n /c:"新值" src\*.py docs\*.md tests\*.py

:: 若使用 PowerShell
Get-ChildItem -Recurse -Include *.py,*.md,*.yaml,*.bat,*.sh | Select-String "旧值"
```

### 规则2：跨平台兼容性规则

**规则内容**：
> **所有核心功能必须支持跨平台（至少Windows和Linux）**

**禁止事项**：
- ❌ 硬编码Windows路径（如`D:\\tools\\`）
- ❌ 使用Windows专用命令（如`explorer`, `taskkill`）而不提供跨平台替代
- ❌ 在核心代码中使用平台特定语法

**要求事项**：
- ✅ 使用Python实现跨平台功能
- ✅ 使用`platform.system()`检测操作系统
- ✅ 为不同平台提供fallback机制
- ✅ 批处理脚本(.bat)可以Windows专用，但必须提供对应的Shell脚本(.sh)

**跨平台检查清单**：
- [ ] 路径处理使用`os.path.join()`或`pathlib.Path`
- [ ] 命令执行使用`subprocess`而非shell命令
- [ ] 文件操作使用Python标准库
- [ ] 平台检测使用`platform`模块
- [ ] Windows专用脚本提供Linux对应版本

---

### 规则3：配置驱动规则

**规则内容**：
> **所有可配置参数应通过配置文件管理，避免硬编码**

**要求**：
- ✅ 使用YAML配置文件（`jmeter_config.yaml`）
- ✅ 支持环境变量覆盖
- ✅ 提供合理的默认值
- ✅ 配置变更不修改代码

---

### 规则4：文档同步规则

**规则内容**：
> **代码变更必须同步更新相关文档**

**要求**：
- ✅ 新增功能 → 更新需求文档
- ✅ 修改接口 → 更新API规范
- ✅ 架构变更 → 更新设计文档
- ✅ 测试用例 → 更新测试文档

---

## 📝 规则应用示例

### 示例1：服务器信息变更

**场景**：服务器IP从`192.168.24.100`变更为`192.168.24.45`

**执行步骤**：
1. 搜索所有文件：
   ```bash
   grep -r "192.168.24.100" src/ docs/ tests/ *.md *.bat *.sh
   ```

2. 更新范围：
   - ✅ `jmeter_config.yaml`
   - ✅ `docs/api-specs/cli-commands.md`
   - ✅ `docs/requirements/functional-requirements.md`
   - ✅ `docs/requirements/acceptance-criteria.md`
   - ✅ `docs/implementation/development-plan.md`
   - ✅ `docs/DEVELOPMENT_PROGRESS.md`
   - ✅ 所有其他提及的文档

3. 验证更新：
   ```bash
   grep -r "192.168.24.100" src/ docs/ tests/
   # 应该只返回历史记录或问题描述，不应有实际配置
   ```

### 示例2：路径变更

**场景**：配置文件路径从`data/configs/`变更为`src/jmeter_test_suite/infrastructure/config/`

**执行步骤**：
1. 搜索所有引用
2. 更新所有文档中的路径说明
3. 更新INSTALL.md中的路径示例
4. 验证所有路径引用

## 📌 重要提醒

⚠️ **违反规则的后果**：
- 配置不一致导致功能异常
- 文档过时导致用户困惑
- 跨平台兼容性问题
- 代码审查不通过

✅ **正确做法**：
- 每次变更都执行全项目搜索
- 更新所有相关文件
- 验证更新完整性
- 记录变更日志

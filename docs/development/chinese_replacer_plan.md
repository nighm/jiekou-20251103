# 中文替换工具开发计划（已暂停）

> 说明：随着语言相关的规范要求取消，本计划暂不执行，后续若重新引入相关需求再恢复评估。

## 背景与现状
- 现有 `tools/non_ascii_scanner.py` 仅支持检测非 ASCII 内容，不提供替换能力。
- 客户要求移除代码中除注释外的中文文本，需求涉及日志、调试信息等字符串。
- 项目遵循 DDD 架构，偏好使用 YAML 配置、`result/jmeter` 目录存放自动化输出。

## 目标
- 基于 AST/CST 实现精准的中文文本扫描与替换，避免误处理注释或结构化代码。
- 支持“仅扫描（dry-run）”与“执行替换”两种模式，替换逻辑可配置。
- 生成可追溯报告，便于人工复核和合规留档。
- 保持工具与现有质量流水线兼容，可被 `quality_suite.py` 调用。

## 范围
- 首期仅覆盖 Python 代码：`src/`、`tests/`、`tools/`。
- 处理对象为字符串字面量（含 `f-string`）、日志调用参数；跳过注释和文档字符串。
- 通过 YAML 配置维护中文→英文映射及忽略清单，禁止硬编码。
- 报告输出至 `result/jmeter/chinese_replacer_report.json`（或 `.yaml`），遵循现有目录规范。

## 主要交付物
- `tools/chinese_replacer.py`：核心权限脚本，提供命令行接口与可重用函数。
- `tools/config/chinese_replacements.yaml`：替换映射与忽略规则。
- `tests/unit/tools/test_chinese_replacer.py`：单元测试覆盖扫描、替换关键路径。
- `docs/` 更新：本计划、后续使用说明或操作手册。
- 质量流水线更新：`tools/quality_suite.py` 新增阶段调用。

2. **工具实现阶段**
   - 编写 `chinese_replacer.py`：
     - 封装 AST 访问器，扫描字符串节点并识别中文字符。

## 风险与应对
- **AST 兼容性**：`libcst` 对 Python 3.12 支持需确认；若存在问题，可回退到 `ast` + 自行重建源代码方案。
- **替换准确性**：复杂动态字符串可能无法一键替换，需生成报告提醒人工处理。
- **配置维护**：中文→英文映射量大时需建立校验机制；可在 YAML 中增加校验字段或使用脚本验证。
- **性能问题**：全量扫描耗时可能较长，可在脚本中加入增量模式或多进程支持作为优化选项。

## 验收标准
- 能够在 dry-run 模式下输出所有中文字符串位置及建议替换信息。
- 在 apply 模式下对 YAML 中定义的中文内容进行自动替换，并写入报告。
- `quality_suite.py` 中新阶段执行成功，且失败时不会中断整个流水线。
- `pytest`、`ruff`、`mypy` 等质量检查全部通过。

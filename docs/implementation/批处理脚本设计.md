## 🎯 设计概述

### 设计目标

`一键运行-单个接口.bat`的设计目标是为Windows用户提供：
1. **零配置启动**: 用户只需双击即可执行，无需手动配置环境
2. **自动环境准备**: 自动检查和安装必要的依赖
3. **清晰的执行流程**: 明确的步骤提示和进度显示
4. **友好的错误处理**: 详细的错误信息和解决建议
5. **便捷的结果查看**: 自动打开结果文件夹

### 架构设计

```
一键运行-单个接口.bat
├── 初始化阶段
│   ├── UTF-8 编码设置
│   └── 欢迎与步骤提示
├── 环境准备阶段
│   ├── Python 环境诊断
│   ├── PYTHONPATH 配置
│   └── 依赖检测与静默安装
├── 测试前信息阶段
│   ├── JMeter 检查策略提示
│   ├── 配置信息输出 (config-info)
│   └── 模式信息输出 (mode-info)
├── 测试执行阶段
│   ├── JTL 日志文件初始化
│   ├── PowerShell 实时进度窗口
│   └── all 命令执行与退出码捕获
├── 失败兜底阶段
│   ├── 关闭实时窗口
│   ├── 失败触发 report 补救
│   └── 错误信息与暂停退出
└── 成功收尾阶段
    ├── 打开结果目录（open-result → explorer 降级）
    ├── 成功摘要信息
    └── 配置&支持提示
```

## 🏗️ 模块设计

### 模块1: 初始化模块

**功能**: 脚本初始化和基础设置

**实现细节**:
```batch
@echo off
chcp 65001 >nul
REM 版本信息和说明
```

**关键点**:
- `@echo off`: 关闭命令回显，保持输出整洁
- `chcp 65001`: 设置UTF-8编码，确保emoji和多语言字符显示
- `>nul`: 重定向输出到空设备，隐藏命令执行输出

### 模块2: Python环境检查模块

**功能**: 检查Python是否安装并可用

**实现细节**:
```batch
python --version >nul 2>&1
if %errorlevel% neq 0 (
    echo ❌ Python not found
    echo 💡 Please install Python 3.12+ first
    echo 💡 Or use Python installer in data/tools/ folder
    pause
    exit /b 1
)

echo ✅ Python OK
python --version
```

**设计要点**:
- **错误检测**: 使用`%errorlevel%`判断Python是否可用
- **辅助提示**: 明确指出可在`data/tools/`目录找到离线安装包
- **优雅退出**: 失败时暂停并返回错误码，避免继续执行
- **版本回显**: 成功后显示实际Python版本，方便排查环境差异

### 模块3: 依赖准备模块

**功能**: 配置Python搜索路径并自动安装依赖

**实现细节**:
```batch
echo.
echo 📦 Checking and installing dependencies...

set PYTHONPATH=%~dp0src;%PYTHONPATH%

python -c "import jmeter_test_suite; print('✅ Project already installed')" >nul 2>&1
if %errorlevel% equ 0 (
    echo ✅ Project package already installed
    goto deps_done
)

echo ⏳ Installing dependencies (first time setup)...

echo    📈 Upgrading pip...
python -m pip install --upgrade pip >nul 2>&1

echo    📚 Installing Python packages...
python -m pip install -e .[dev] >nul 2>&1
if %errorlevel% neq 0 (
    echo    ⚠️ Using China mirror for faster download...
    python -m pip install -i https://pypi.tuna.tsinghua.edu.cn/simple -e .[dev] >nul 2>&1
)

echo ✅ Dependencies installed successfully

:deps_done
```

**设计要点**:
- **路径预设**: 在安装前设置`PYTHONPATH`，保证导入`jmeter_test_suite`
- **静默检测**: 通过`python -c`检测包是否已安装，减少重复操作
- **分步骤提示**: 每个安装步骤均输出明确的进度信息
- **镜像兜底**: 失败后自动切换清华源，提高国内环境适配力
- **统一出口**: 使用`:deps_done`标签与`goto`保证流程只初始化一次

### 模块6: 测试执行与实时监控模块

**功能**: 启动性能测试并在独立窗口实时展示进度

**实现细节**:
```batch
echo.
echo 🎯 Starting performance tests...
echo ⏳ Please wait, this may take several minutes...
echo 📊 Progress will be shown below...
echo.

set JMETER_LATEST_LOG=result\jmeter_latest.log
if exist "%JMETER_LATEST_LOG%" del "%JMETER_LATEST_LOG%"

echo 🛰️ Opening live JMeter progress window...
start "JMeter Live" powershell -NoLogo -NoProfile -Command "if (Test-Path '%JMETER_LATEST_LOG%') { Get-Content -Path '%JMETER_LATEST_LOG%' -Wait -Tail 5 } else { Write-Output 'Waiting for %JMETER_LATEST_LOG%...'; while (-not (Test-Path '%JMETER_LATEST_LOG%')) { Start-Sleep -Seconds 1 }; Get-Content -Path '%JMETER_LATEST_LOG%' -Wait -Tail 5 }"

python -m jmeter_test_suite all
set TEST_EXITCODE=%ERRORLEVEL%

echo 📴 Closing live JMeter progress window...
taskkill /FI "WINDOWTITLE eq JMeter Live" >nul 2>&1
```

**设计要点**:
- **日志文件复用**: 使用`result/jmeter_latest.log`作为 CLI 与 PowerShell 的共享通道
- **非阻塞监控**: 通过`start`开启独立窗口，避免阻塞主脚本流程
- **容错逻辑**: PowerShell 命令在日志尚未生成时会循环等待，提升鲁棒性
- **资源清理**: 测试结束后主动调用`taskkill`关闭监控窗口，避免残留进程

**相关文档**:
- [CLI命令规范](../api-specs/cli命令.md)

### 模块7: 失败补救模块

**功能**: 处理测试失败并尝试生成补救报告

**实现细节**:
```batch
if "%TEST_EXITCODE%"=="0" goto final_success

echo ⚠️ Tests reported failure (likely nmon). Trying to generate report from JTL files...
python -m jmeter_test_suite report
if %ERRORLEVEL%==0 (
    echo ✅ Report generated despite monitor failure. Treating as success.
    goto final_success
) else (
    goto failure_path
)

:failure_path

echo.
echo ❌ Performance tests failed!
echo 💡 Please check the error messages above
echo 💡 Common issues:
echo    - Server connection problems
echo    - Configuration file errors
echo    - Insufficient system resources
echo    - Slave node not started (if distributed enabled)
echo    - Network connectivity issues (if distributed enabled)
echo    - JMeter version mismatch (if distributed enabled)
echo.
echo Press any key to exit...
pause >nul
exit /b %TEST_EXITCODE%
```

**设计要点**:
- **退出码判断**: 将测试命令的结果缓存至`TEST_EXITCODE`
- **补救策略**: 自动执行`report`生成报告，解决 nmon 失败导致的误报
- **多种提示**: 提供常见故障列表，便于用户快速定位问题
- **统一出口**: 所有失败路径均通过`failure_path`处理并返回原始退出码

**设计要点**:

- **中英文结合**: 保留“完成”提示以体现版本信息

## 🔄 执行流程设计

### 正常执行流程

```
开始
  ↓
设置UTF-8编码
  ↓
显示欢迎信息与步骤提示
  ↓
检查Python环境
  ├─ 失败 → 提示安装路径 → 暂停 → 退出
  └─ 成功 → 继续
  ↓
配置PYTHONPATH并检查项目依赖
  ├─ 已安装 → 跳转到 deps_done
  └─ 未安装 → 分步骤静默安装
        ├─ 标准源失败 → 切换清华镜像
        └─ 安装完成 → 输出成功提示
  ↓
提示JMeter将在执行阶段检测
  ↓
调用 config-info 显示配置信息
  ↓
调用 mode-info 显示模式信息
  ↓
准备实时监控
  ├─ 清理旧的 jmeter_latest.log
  └─ 启动 PowerShell 进度窗口
  ↓
执行 all 命令
  ├─ 退出码=0 → 跳转 final_success
  └─ 退出码≠0 → 尝试执行 report 补救
        ├─ report 成功 → 视作成功 → 跳转 final_success
        └─ report 失败 → 跳转 failure_path
  ↓
:final_success
  ↓
展示成功摘要
  ↓
调用 open-result 打开结果目录（失败→explorer）
  ↓
输出配置与支持信息
  ↓
pause 等待用户
  ↓
结束
```

### 错误处理流程

```
检测到错误/异常退出码
  ↓
判断阶段
  ├─ Python 检查失败
  │   └─ 指向 data/tools 安装包 → 暂停 → 退出
  ├─ 依赖安装失败
  │   └─ 切换清华镜像 → 若仍失败则继续抛出错误
  └─ all 命令失败
      ├─ 关闭 PowerShell 进度窗口
      ├─ 尝试执行 report 生成Excel
      │   ├─ report 成功 → 输出补救成功 → final_success
      │   └─ report 失败 → 进入 failure_path
      └─ failure_path 输出常见问题 → 暂停 → 带原始退出码退出
```

## 🔧 技术实现细节

### 批处理脚本技巧

1. **错误检测**:
   ```batch
   command >nul 2>&1
   if %errorlevel% neq 0 (
       REM 处理错误
   )
   ```

2. **条件跳转**:
   ```batch
   if %errorlevel% equ 0 (
       goto success
   ) else (
       goto failure
   )
   ```

3. **路径处理**:
   ```batch
   set PYTHONPATH=%~dp0src;%PYTHONPATH%
   ```
   `%~dp0` - 脚本所在目录（带反斜杠）

4. **输出重定向**:
   ```batch
   command >nul 2>&1  REM 隐藏输出
   ```

5. **暂停等待**:
   ```batch
   pause       REM 显示"按任意键继续"
   pause >nul  REM 不显示提示信息
   ```

### 字符编码处理

```batch
chcp 65001 >nul
```
- `chcp 65001`: 设置代码页为UTF-8
- `>nul`: 隐藏命令输出
- 确保emoji和多语言字符正确显示

### 环境变量设置

```batch
set PYTHONPATH=%~dp0src;%PYTHONPATH%
```
- 追加到现有PATH，不覆盖
- 仅对当前会话有效
- 不影响系统环境变量

## 🛡️ 错误处理设计

### 错误分类

1. **环境错误**:
   - Python未安装
   - 处理: 显示提示，暂停等待，退出

2. **依赖错误**:
   - 依赖安装失败
   - 处理: 尝试镜像源，继续执行

3. **配置错误**:
   - 配置文件不存在或格式错误
   - 处理: CLI命令会处理，脚本传递错误信息

4. **执行错误**:
   - 测试执行失败
   - 处理: 显示详细错误和常见问题建议

## 📝 编码规范

### 命名规范

- **变量**: 使用大写字母，下划线分隔（如`PYTHONPATH`）
- **标签**: 使用小写字母，下划线分隔（如`:deps_done`）
- **注释**: 使用`REM`开头，清晰描述功能

### 注释规范

```batch
REM 功能模块标题
REM 详细说明功能和作用

REM 关键步骤说明
command

REM 错误处理说明
if error (
    REM 错误处理逻辑
)
```

### 格式规范

- 使用4个空格缩进（批处理脚本通常不严格，但保持一致性）
- 相关命令分组，使用空行分隔
- 长命令可以换行，但要注意语法

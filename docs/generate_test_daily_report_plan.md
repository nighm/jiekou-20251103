# generate_test_daily_report.py 优化计划

## 目标
- 明确“正常日报”和“异常日报”两种场景的判定标准与输出差异。
- 仅输出 Excel 对外日报，取消 Markdown 文本生成需求。
- 确保正常场景下仍可记录测试中发现的缺陷；异常场景提供完整问题证据链。

## 当前现状与问题
- 当前脚本未区分正常/异常模板，部分失败即被视作异常，导致报告结构与期望不符。
- 外发日报需要通过 Excel 实现双模板，但现有实现没有针对正常/异常分别处理封面与问题分析。
- 打包逻辑默认尝试下载服务器日志与配置，正常场景不一定需要，且存在权限不足告警。

## 场景定义
- **正常日报**：所有 JTL 文件样本数齐全，无卡死/缺失；允许存在响应失败或成功率低的缺陷。
- **异常日报**：检测到样本缺失、卡死、关键流程中断或其他导致 JTL 不完整的情况。

## 模板差异要点
- **封面摘要**：正常模式强调测试顺利完成；异常模式突出故障摘要与影响。
- **问题章节**：正常模式记录缺陷列表（可附成功率、响应时间等数据）；异常模式需要详细的问题分析、日志/配置引用、证据截图。
- **附件说明**：正常模式可简化，仅列报告与必要数据；异常模式需列出日志、配置、截图等证据路径。

## 实施步骤
1. **结果判定函数**：编写独立方法，根据 JTL 指标判定是否属于异常场景。
2. **模板分支**：重构封面、问题分析、数据清单等函数，支持正常/异常两套结构。
3. **Excel 生成调整**：按场景调用不同模板组合，仅输出 Excel 文件；移除 Markdown 输出逻辑。
4. **打包策略优化**：正常场景可跳过服务器日志/配置抓取；异常模式保留现有打包流程并增强告警提示。
5. **验证**：
   - 使用当前 result 数据验证正常日报生成，确认 Excel 符合预期。
   - 构造或回放异常数据验证异常日报输出。
   - 汇总运行告警并提出后续优化建议。

## 验证与交付
- 交付内容：`reports/测试日报_心跳接口压测_YYYYMMDD_HHMMSS.xlsx`（按场景生成对应模板）。
- 验证清单：
  - 场景判定是否准确。
  - 各工作表标题、内容是否符合模板差异设计。
  - 运行告警是否符合预期并在必要时输出。
- 后续改进：根据验证结果调整判定阈值、完善日志抓取权限、补充截图等证据流程。

## 2. 文档格式选择策略

### 2.1 格式选择原则

根据GB/T 8567-2006标准和实际项目实践，文档格式选择遵循以下原则：

| 文档类型 | 推荐格式 | 备选格式 | 使用场景 | 说明 |
|---------|---------|---------|---------|------|
| **编写阶段文档** | Markdown (.md) | LaTeX | 日常编写、版本控制 | 便于Git管理，支持协作编辑 |
| **正式发布文档** | PDF (.pdf) | - | 正式交付、归档保存 | 格式固定，跨平台一致，使用LaTeX生成 |
| **内部协作文档** | Markdown (.md) | - | 团队内部协作 | 易于编辑和版本控制 |
| **对外正式文档** | PDF (.pdf) | - | 对外交付、合同文档 | 正式性强，不可编辑，格式确定性 |
| **图表文件** | PNG/SVG (.png/.svg) | JPG/PDF | 插入文档的图表 | 矢量图优先SVG，位图用PNG |
| **附件文件** | PDF | Excel/PPT | 参考文档、附件 | 根据内容类型选择 |

### 2.2 本项目格式选择

**主文档格式**：Markdown (.md)
- 理由：便于版本控制、团队协作、技术文档编写
- 工具：VS Code、Mark Text、Typora等编辑器
- 版本控制：Git仓库管理
- **重要说明**：Markdown本身不支持字号、行距等格式设置，格式控制通过转换工具实现

**发布文档格式**：PDF (.pdf) ⚠️ **关键格式**
- 理由：正式交付、格式固定、便于归档，格式确定性
- 生成方式：使用LaTeX将Markdown转换为PDF，确保格式完全一致
- LaTeX模板：必须使用符合GB/T 8567-2006标准的LaTeX模板（`templates/gb8567-template.tex`）
- 转换工具：使用`tools/convert_md_to_pdf.bat`（Windows）或`tools/convert_md_to_pdf.sh`（Linux/macOS）
- **LaTeX优势**：格式完全由代码控制，同样的代码总是产生同样的结果，不会出现格式错乱

### 2.3 格式实现方式

**关键理解**：
- ⚠️ **Markdown是内容标记语言，不是格式控制语言**
- ✅ **格式控制需要在转换阶段通过工具实现**
- ✅ **格式规范主要针对最终发布的PDF/DOCX文档**

**格式实现流程**：

```
Markdown编写（关注内容结构）
    ↓
添加YAML元数据（格式参数）
    ↓
使用转换工具（pandoc等）
    ↓
应用格式模板/样式
    ↓
PDF/DOCX输出（符合标准格式）
    ↓
格式验证（确保符合要求）
```

## 3. 文档结构要求

### 3.1 封面页格式

封面页必须包含以下信息，格式如下：

```
┌─────────────────────────────────────────┐
│                                          │
│         [项目名称]                       │
│                                          │
│      [文档编号]                           │
│      [文档名称]                           │
│                                          │
│                                          │
│  编制单位：[单位名称]                     │
│  编制日期：YYYY-MM-DD                    │
│  版本号：v1.0                            │
│                                          │
│                                          │
│    [编制单位Logo（可选）]                 │
│                                          │
└─────────────────────────────────────────┘
```

**格式要求**：
- 文档名称：黑体，小一号（24pt），居中
- 文档编号：黑体，三号（16pt），居中
- 项目名称：黑体，二号（22pt），居中
- 其他信息：宋体，四号（14pt），居中
- 页面：A4，上下左右边距均为2.5cm

### 3.2 文档变更记录表格式

| 项目 | 格式要求 | 示例 |
|-----|---------|------|
| 表格宽度 | 占页面宽度的90% | - |
| 表格边框 | 外边框粗线（1.5pt），内边框细线（0.5pt） | - |
| 表头背景 | 浅灰色（RGB: 240,240,240） | - |
| 表头字体 | 黑体，五号（10.5pt），加粗 | - |
| 表格内容 | 宋体，五号（10.5pt） | - |
| 行高 | 最小值0.8cm | - |
| 对齐方式 | 版本号、日期居中，其他左对齐 | - |

### 3.3 目录格式

- **生成方式**：自动生成（Markdown编辑器自动生成，或使用工具生成）
- **格式要求**：
  - 目录标题：黑体，三号（16pt），居中
  - 目录内容：宋体，小四号（12pt）
  - 章节编号：使用阿拉伯数字，如1、1.1、1.1.1
  - 页码：右对齐，使用点线连接
  - 行距：单倍行距

### 3.4 正文结构

**章节标题格式**：
- 一级标题（章节）：黑体，小二号（18pt），加粗，段前12pt，段后6pt
- 二级标题（小节）：黑体，三号（16pt），加粗，段前6pt，段后3pt
- 三级标题（子节）：黑体，四号（14pt），加粗，段前3pt，段后3pt
- 四级标题（条）：黑体，小四号（12pt），加粗，段前3pt，段后0pt

**正文段落格式**：
- 字体：宋体，小四号（12pt）
- 行距：1.5倍行距
- 段前：0.5行（6pt）
- 段后：0.5行（6pt）
- 首行缩进：2字符（中文段落）
- 对齐方式：两端对齐

**列表格式**：
- 无序列表：使用项目符号（•、○、-），悬挂缩进2字符
- 有序列表：使用阿拉伯数字（1、2、3），悬挂缩进2字符
- 列表项行距：单倍行距
- 列表项间距：0.3行

## 4. 字体和字号规范

### 4.1 字体选择原则

| 文字类型 | 字体 | 理由 |
|---------|------|------|
| **中文正文** | 宋体 | 标准中文文档字体，易读性好 |
| **中文标题** | 黑体 | 突出重点，层次分明 |
| **英文正文** | Times New Roman | 标准英文文档字体 |
| **英文标题** | Arial | 简洁现代 |
| **代码文本** | Courier New / Consolas | 等宽字体，便于对齐 |
| **数学公式** | Times New Roman | 数学公式标准字体 |
| **表格文字** | 宋体（中文）/ Times New Roman（英文） | 表格空间有限，使用标准字体 |

### 4.2 字号详细规范

| 文字类型 | 字号 | 磅值 | 应用场景 |
|---------|------|------|---------|
| **文档标题（封面）** | 小一号 | 24pt | 封面文档名称 |
| **一级标题（章节）** | 小二号 | 18pt | 1、2、3... |
| **二级标题（小节）** | 三号 | 16pt | 1.1、1.2、1.3... |
| **三级标题（子节）** | 四号 | 14pt | 1.1.1、1.1.2... |
| **四级标题（条）** | 小四号 | 12pt | 1.1.1.1、1.1.1.2... |
| **正文** | 小四号 | 12pt | 正文段落 |
| **表格文字** | 五号 | 10.5pt | 表格内容 |
| **表格标题** | 小五号 | 9pt | 表格标题 |
| **图表标题** | 小四号 | 12pt | 图标题、表标题 |
| **图表说明** | 五号 | 10.5pt | 图表下方的说明文字 |
| **代码文本** | 五号 | 10.5pt | 代码块、行内代码 |
| **页眉页脚** | 小五号 | 9pt | 页眉、页脚文字 |
| **注释** | 小五号 | 9pt | 脚注、注释 |

### 4.3 字体加粗规则

- **必须加粗**：所有标题、表格表头、重要术语首次出现
- **可选加粗**：强调内容、关键词、重要数字
- **禁止加粗**：正文段落、正文中的普通文字

## 5. 段落格式规范

### 5.1 行距规范

| 内容类型 | 行距 | 说明 |
|---------|------|------|
| **正文段落** | 1.5倍行距 | 标准行距，易读性好 |
| **标题与正文之间** | 单倍行距 | 标题段后+正文段前=适当间距 |
| **列表项** | 单倍行距 | 列表项之间紧凑 |
| **表格内容** | 单倍行距 | 表格空间有限 |
| **代码块** | 单倍行距 | 代码通常行数较多 |

### 5.2 段间距规范

| 段落类型 | 段前 | 段后 | 说明 |
|---------|------|------|------|
| **一级标题** | 12pt | 6pt | 与上一章节分隔明显 |
| **二级标题** | 6pt | 3pt | 与上一小节分隔 |
| **三级标题** | 3pt | 3pt | 适当的间距 |
| **正文段落** | 0.5行（6pt） | 0.5行（6pt） | 标准段落间距 |
| **列表项** | 0.3行（3.6pt） | 0.3行（3.6pt） | 列表项之间紧凑 |
| **表格前后** | 6pt | 6pt | 表格与正文的间距 |

### 5.3 缩进规范

- **首行缩进**：
  - 中文正文段落：2字符（7.5mm）
  - 英文正文段落：0（不使用首行缩进）
  - 列表项：悬挂缩进2字符

- **段落缩进**：
  - 正文段落：左右缩进均为0
  - 引用段落：左右各缩进2字符，使用特殊格式（如浅灰色背景）

## 6. 页面设置规范

### 6.1 页面规格

- **纸张大小**：A4（210mm × 297mm）
- **方向**：纵向（Portrait）
- **页边距**：
  - 上边距：2.5cm（用于页眉）
  - 下边距：2.5cm（用于页脚）
  - 左边距：2.5cm（装订线）
  - 右边距：2.5cm

### 6.2 页眉页脚格式

**页眉格式**：
- 位置：页眉高度1.5cm，距离页面顶部1.25cm
- 左侧：文档名称（黑体，小五号，9pt）
- 右侧：版本号（黑体，小五号，9pt）
- 分隔线：页眉下方0.5pt细线，颜色RGB(200,200,200)

**页脚格式**：
- 位置：页脚高度1.5cm，距离页面底部1.25cm
- 左侧：编制单位名称（宋体，小五号，9pt）
- 中间：页码（宋体，小五号，9pt），格式：第X页 共Y页
- 右侧：编制日期（宋体，小五号，9pt），格式：YYYY-MM-DD

### 6.3 页码格式

- **编号方式**：阿拉伯数字（1、2、3...）
- **起始页码**：目录页从罗马数字开始（i、ii、iii...），正文从1开始
- **位置**：页脚居中
- **格式**：第X页 共Y页（如：第1页 共50页）

## 7. 编号规则规范

### 7.1 章节编号规则

- **编号方式**：阿拉伯数字分级编号
- **编号格式**：
  - 一级：1、2、3...
  - 二级：1.1、1.2、1.3...
  - 三级：1.1.1、1.1.2、1.1.3...
  - 四级：1.1.1.1、1.1.1.2...（仅在必要时使用）

- **编号规则**：
  - 章节编号后必须有一个空格，再跟标题文字
  - 示例：`1. 引言`、`1.1 目的`、`1.1.1 文档目的`

### 7.2 图表编号规则

**图表编号格式**：
- 图形：`图[章节号]-[序号]`，如`图1-1`、`图2-3`
- 表格：`表[章节号]-[序号]`，如`表1-1`、`表2-3`

**图表标题格式**：
- 图形标题：位于图形下方，居中，格式：`图X-Y [图形标题]`
- 表格标题：位于表格上方，居中，格式：`表X-Y [表格标题]`
- 字体：黑体，小四号（12pt）

**图表说明格式**：
- 位置：图表标题下方
- 格式：宋体，五号（10.5pt），左对齐
- 内容：简要说明图表的内容、数据来源、用途等

### 7.3 公式编号规则

- **编号格式**：`([章节号]-[序号])`，如`(1-1)`、`(2-3)`
- **位置**：公式右侧，右对齐
- **字体**：Times New Roman，五号（10.5pt）

### 7.4 引用格式规则

**引用标准**：
- 格式：`GB/T 8567-2006《计算机软件文档编制规范》`
- 首次出现：使用全称
- 再次出现：可使用简称`GB/T 8567-2006`

**引用文档**：
- 格式：`[文档编号]`或`（文档编号）`
- 示例：`[FSR-001]`、`（可行性研究报告）`

**引用图表**：
- 格式：`见图X-Y`、`如表X-Y所示`
- 示例：`见图1-1`、`如表2-3所示`

- **边框**：无

## 11. 文档命名和编号规范

### 11.1 文件命名格式

```
[文档编号]_[文档名称]_v[版本号].[扩展名]
```

**详细规则**：
- **文档编号**：按照GB/T 8567-2006标准（如FSR、PDP、SRS）
- **文档名称**：中文全称，与标准文档名称一致
- **版本号**：格式`v[主版本号].[次版本号].[修订号]`
- **扩展名**：
  - `.md`：Markdown源文件
  - `.pdf`：PDF发布文件（使用LaTeX生成）
  - `.tex`：LaTeX模板文件

**示例**：
- `FSR_可行性研究报告_v1.0.md`
- `PDP_项目开发计划_v1.1.md`
- `SRS_软件需求说明书_v1.0.1.md`

### 11.2 文档编号格式

```
[项目编号]-[文档类型编号]-[序号]
```

**详细规则**：
- **项目编号**：项目唯一标识符（如PROJ、JMETER-TEST）
- **文档类型编号**：按照GB/T 8567-2006标准
  - FSR：可行性研究报告
  - PDP：项目开发计划
  - SRS：软件需求说明书
  - DRS：数据要求说明书
  - HLD：概要设计说明书
  - DLD：详细设计说明书
  - DBD：数据库设计说明书
  - MDD：模块开发卷宗
  - TP：测试计划
  - TAR：测试分析报告
  - UM：用户手册
  - OM：操作手册
  - MPR：开发进度月报
  - PSR：项目开发总结报告
- **序号**：同一类型文档的序号，使用三位数字（001、002...）

**示例**：
- `PROJ-FSR-001`：项目可行性研究报告

## 12. Markdown转PDF格式规范（使用LaTeX）

### 12.1 发布文档格式要求

**重要说明**：
- ⚠️ **发布文档使用PDF格式**：PDF作为最终交付物，格式固定，跨平台一致
- ⚠️ **使用LaTeX生成PDF**：LaTeX格式完全由代码控制，同样的代码总是产生同样的结果，不会出现格式错乱
- ⚠️ **避免维护两套文档**：只维护Markdown源文件，通过工具自动转换为PDF

**工作流程**：
```
Markdown编写（源文件）
    ↓
Pandoc转换为LaTeX（使用LaTeX模板）
    ↓
LaTeX编译生成PDF（格式完全确定）
    ↓
PDF输出（最终交付物）
```

**转换工具**：
- **Windows**：`tools/convert_md_to_pdf.bat`
- **Linux/macOS**：`tools/convert_md_to_pdf.sh`
- **直接命令**：`pandoc input.md -o output.pdf --template=templates/gb8567-template.tex`

### 12.2 LaTeX模板要求

LaTeX模板必须包含以下格式定义：

1. **正文样式（Normal）**：
   - 字体：宋体（中文）、Times New Roman（英文）
   - 字号：12pt（小四号）
   - 行距：1.5倍行距
   - 首行缩进：2字符（0.75cm）
   - 段落间距：段前6pt，段后6pt
   - 对齐方式：两端对齐

2. **标题样式（Heading 1-4）**：
   - 一级标题：黑体18pt，段前12pt，段后6pt
   - 二级标题：黑体16pt，段前6pt，段后3pt
   - 三级标题：黑体14pt，段前3pt，段后3pt
   - 四级标题：黑体12pt，段前3pt，段后0pt

3. **表格样式**：
   - 外边框：1.5pt粗线
   - 内边框：0.5pt细线
   - 表头背景：浅灰色（RGB: 240,240,240）
   - 表头字体：黑体10.5pt，加粗，居中
   - 表格内容：宋体10.5pt，左对齐（序号列居中）

4. **页面设置**：
   - 页面大小：A4（21cm × 29.7cm）
   - 页边距：上下2.5cm，左右2.5cm
   - 页眉页脚：符合GB/T 8567-2006标准

**LaTeX模板文件**：`templates/gb8567-template.tex`

### 12.3 LaTeX格式确定性优势

**LaTeX的核心优势**：
- ✅ **代码即格式**：格式由代码定义，不是由软件"猜测"
- ✅ **确定性输出**：同样的代码，总是产生同样的结果
- ✅ **不会错乱**：除非修改代码，格式不会改变
- ✅ **可重复性**：编译100次，PDF格式完全一样

**就像编程**：
```python
def add(a, b):
    return a + b

add(1, 1)  # 总是返回2，不会变成3
```

**LaTeX也是一样**：
```latex
\newcommand{\myfontsize}{14pt}

{\fontsize{\myfontsize}{18pt} 文字}  # 总是14pt，不会变成12pt或16pt
```

**格式保证**：
- ✅ 所有段落格式完全一致：首行缩进、行距、字体完全相同
- ✅ 所有标题格式完全一致：字体、字号、间距完全相同
- ✅ 不会出现"前面4号，后面3号"的情况：格式由代码控制，完全确定

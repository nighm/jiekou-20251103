# 功能需求 v1.1

## 🎯 概述

本文档定义了 JMeter 和 nmon 性能测试数据收集与 Excel 报告生成工具 v1.1 的功能需求。v1.1 在保持核心流程简单直观的前提下，对默认配置、日志管理、分布式压测等要求进行了更新，以便后续 CI/CD 自动化能够直接复用。

## 📋 核心功能需求

### FR-001: JMeter数据收集
**功能描述**: 执行JMeter测试，收集性能测试数据

**输入参数**:
- JMX 文件路径（从 YAML 配置读取，当前默认 `09_device_heartbeat.jmx`）
- 线程数范围（从 YAML 配置读取，当前默认 `"7000 7000 1000"`，代表单一线程值 7000）
- 循环次数范围（从 YAML 配置读取，当前默认 `"100 100 0"`，代表单一循环值 100）
- 输出目录（从 YAML 配置读取，默认 `./result`）

**处理逻辑**:
1. 从YAML配置中读取测试参数
2. 解析 `thread_range` 与 `loop_range`，当步长为 0 时按单值处理
3. 执行批量 JMeter 测试（线程数 × 循环数组合）
4. 对每个组合执行 JMeter 命令：`jmeter -n -t [jmx] -l [jtl] -e -o [html] -Jthreads=[threads] -Jloops=[loops]`
5. 等待每轮测试完成，打印执行日志
6. 检查结果文件，并将旧文件移动到 `result/old/`
7. 提取性能数据（响应时间、TPS、错误率等）

**输出结果**:
- 多个 JTL 结果文件（每轮测试一个）
- 多个 HTML 报告目录（每轮测试一个）
- 性能数据提取结果
- 批量执行状态报告（成功/失败）
- 最新压测日志、副本日志以及 stdout/stderr 文件

**技术规范**:
- 支持 JMeter 5.0+
- 默认超时：30 分钟（可通过配置调整）
- 内存限制：2GB
- 批量执行：支持线程数 × 循环数组合测试（步长为 0 时按单值处理）
- 错误恢复：单轮失败不影响其他轮次
- 文件命名：包含线程数、循环数和时间戳
- 日志管理：自动归档旧文件，保障 result 目录整洁

### FR-002: nmon数据收集
**功能描述**: 通过SSH连接服务器，收集系统资源监控数据

**输入参数**:
- 服务器 IP（默认 `192.168.24.45`）
- 用户名（默认 `test`）
- 密码（默认 `1`）
- 监控时长（默认与 JMeter 测试同步）
- 输出目录（默认 `./result`）

**处理逻辑**:
1. SSH连接到服务器
2. 执行nmon命令开始监控
3. 与JMeter测试同步执行
4. 收集系统资源数据（CPU、内存、IO、网络）
5. 测试结束后停止nmon监控
6. 下载nmon数据文件

**输出结果**:
- nmon 数据文件（CSV 或 nmon 原始格式）
- 系统资源监控数据
- 执行状态（成功/失败）

**技术规范**:
- 支持 SSH 连接（paramiko 库）
- 支持 nmon 工具
- 超时限制：与 JMeter 测试同步
- 连接重试：网络中断时自动重连
- 数据验证：验证nmon数据完整性

### FR-003: Excel报告生成
**功能描述**: 整合JMeter和nmon数据，生成Excel报告

**输入参数**:
- JMeter 数据文件目录（默认扫描 result/ 下所有 JTL）
- nmon 数据文件目录（默认扫描 result/ 下最新文件）
- 输出 Excel 路径（由服务自动命名，可通过参数覆盖）
- 报告模板（可选，默认模板位于 `templates/`）

**处理逻辑**:
1. 解析JMeter JTL文件，提取性能数据
2. 解析nmon CSV文件，提取系统资源数据
3. 数据清洗和格式化
4. 数据关联和整合
5. 生成Excel报告文件
6. 应用报告模板和格式

**输出结果**:
- Excel 报告文件（.xlsx格式）
- 包含 JMeter 性能数据和 nmon 系统资源数据
- 数据可视化图表（可选，取决于配置 `excel.include_charts`）
- 执行状态（成功/失败）

**技术规范**:
- 支持 Excel 文件生成（openpyxl 库）
- 支持数据整合和关联（pandas 库）
- 支持报告模板
- 数据验证：验证输入数据格式和完整性
- 图表生成：支持折线图和柱状图
- 输出目录默认 `./result`

### FR-004: 同步执行管理
**功能描述**: 同步执行JMeter和nmon，确保时间一致性

**输入参数**:
- JMX 文件路径（默认读取配置）
- 线程数（默认读取配置）
- 循环次数（默认读取配置）
- nmon 服务器信息（IP、用户名、密码）
- 输出目录（默认 `./result`）

**处理逻辑**:
1. 启动JMeter测试执行
2. 同时启动nmon监控
3. 确保两者时间同步（±5秒容差）
4. 监控执行状态
5. 等待两者都完成
6. 验证数据完整性

**输出结果**:
- JMeter 执行结果
- nmon 监控结果
- 同步状态报告
- 执行状态（成功/失败）

**技术规范**:
- 支持并发执行
- 时间同步容差：±5秒
- 自动重试机制
- 状态监控
- 支持全局 nmon 文件覆盖整个压测周期

### FR-005: 分布式压测（可选）
**功能描述**: 通过配置文件启用多台 Slave 协同执行压测。

**输入参数**:
- `distributed.enabled`（布尔值，默认 `false`）
- Slave 列表（名称、主机、端口、用户名、密码、JMeter 路径、线程占比）
- Controller 信息（主机、RMI 端口）

**处理逻辑**:
1. 读取分布式配置并创建执行实例
2. 按线程占比分配负载，连接各 Slave
3. 同步启动压测，实时监控执行状态
4. 测试完成后同步停止，汇总执行数据

**输出结果**:
- Slave 执行状态与日志
- 总体测试轮数、成功率、耗时
- 分布式执行摘要（成功/失败）

**技术规范**:
- 默认使用 `ssh_remote` 模式
- 支持自动线程分配、同步启动/停止
- 异常时输出详细错误日志，便于排查

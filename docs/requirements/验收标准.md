# 验收标准 v1.1

## 🎯 概述

JMeter 和 nmon 性能测试数据收集与 Excel 报告生成工具 v1.1 的验收标准，面向基础功能与后续 CI/CD 自动化场景，要求所有结论都可追溯至实际配置与生成文件。

## 📋 功能验收标准

### AC-001: JMeter数据收集
**功能描述**: 执行JMeter测试，收集性能测试数据

**验收条件**:
- [x] 能够通过 `jmeter-test-suite test` 命令执行测试
- [x] 能够从 YAML 配置中读取默认参数（当前线程范围 `"7000 7000 1000"`、循环范围 `"100 100 0"`）
- [x] 当提供线程/循环参数时能执行单轮测试
- [x] 批量模式下能遍历线程 × 循环组合（步长为 0 时按单值处理）
- [x] 能够指定输出目录
- [x] 执行完成后生成对应的 JTL 和 HTML 结果
- [x] 执行前自动归档 `result/` 目录旧文件
- [x] 能够提取性能数据（响应时间、TPS、错误率等）
- [x] 执行过程中输出进度与摘要信息
- [x] 执行失败时提供清晰的错误信息
- [x] 单轮失败不影响其他轮次执行

**测试用例**:
1. **默认配置测试**
   - 输入: 使用 YAML 配置中的默认参数
   - 预期: 成功执行测试，生成 JTL/HTML 文件，提取性能数据

2. **参数边界测试**
   - 输入: 配置中的最小线程数和循环数
   - 预期: 成功执行，提取性能数据

3. **错误处理测试**
   - 输入: 配置文件中缺少必要参数
   - 预期: 显示错误信息，不执行测试

4. **批量执行测试**
   - 输入: 修改 YAML，提供多个线程和循环数组合
   - 预期: 每轮测试独立执行，生成独立的结果文件，并输出完整摘要

### AC-002: nmon数据收集
**功能描述**: 通过SSH连接服务器，收集系统资源监控数据

**验收条件**:
- [x] 能够通过 SSH 连接到服务器
- [x] 能够读取/覆盖服务器 IP、用户名（默认 `test`）、密码
- [x] 能够与 JMeter 测试同步监控时长
- [x] 能够指定输出目录并与测试输出共存
- [x] 能够执行 nmon 命令
- [x] 能够收集系统资源数据（CPU、内存、IO、网络）
- [x] 能够下载 nmon 数据文件
- [x] 连接失败时提供清晰的错误信息
- [x] nmon 执行失败时提供错误信息

**测试用例**:
1. **正常监控**
   - 输入: 使用配置中的默认服务器信息
   - 预期: 成功连接，执行 nmon，收集数据，下载文件

2. **连接失败测试**
   - 输入: 错误的服务器IP或凭据
   - 预期: 显示连接错误信息

3. **监控时长测试**
   - 输入: 调整 `default_duration` 并执行
   - 预期: 按指定时长执行监控

### AC-003: Excel报告生成
**功能描述**: 整合JMeter和nmon数据，生成Excel报告

**验收条件**:
- [x] 能够解析 JMeter JTL 文件
- [x] 能够解析 nmon CSV / nmon 原始文件
- [x] 能够进行数据清洗和格式化
- [x] 能够进行数据关联和整合
- [x] 能够生成 Excel 文件（.xlsx 格式）
- [x] 能够应用报告模板和格式
- [x] 支持批量处理 result 目录
- [x] 输出文件命名符合规范，路径可配置
- [x] 数据格式正确（数字、时间、百分比）
- [x] 文件编码正确

**Excel内容要求**:
- JMeter性能数据（线程数、循环次数、总样本数、成功样本数、失败样本数、平均响应时间、TPS、错误率）
- nmon系统资源数据（CPU使用率、内存使用率、磁盘IO、网络IO）
- 数据关联和整合结果
- 可选的数据可视化图表

**测试用例**:
1. **正常报告生成**
   - 输入: 有效的JTL文件和nmon CSV文件
   - 预期: 生成包含所有数据的Excel文件

2. **批量处理测试**
   - 输入: result 目录中的多个 JTL 和 nmon 文件
   - 预期: 批量生成多个 Excel 报告文件

3. **数据整合测试**
   - 输入: 包含多线程、多循环场景的 JTL 与 nmon 数据
   - 预期: 正确整合数据，生成 Excel 报告

4. **模板应用测试**
   - 输入: 自定义报告模板
   - 预期: 按照模板格式生成Excel报告

## 📊 性能验收标准

### AC-004: 系统性能要求
**功能描述**: 系统性能要求

**验收条件**:
- [x] 启动时间 < 10秒
- [x] 内存使用 < 2GB
- [x] JMeter测试执行超时处理（默认30分钟）
- [x] nmon监控超时处理（默认与JMeter测试同步）
- [x] Excel报告生成时间 < 5分钟

**测试用例**:
1. **性能基准测试**
   - 输入: 标准测试配置
   - 预期: 满足所有性能指标

2. **大数据量处理测试**
   - 输入: 大型JTL文件和nmon数据文件
   - 预期: 在性能要求范围内完成处理

## 🔧 错误处理验收标准

### AC-005: 错误处理机制
**功能描述**: 系统错误处理要求

**验收条件**:
- [x] 所有错误都有明确的错误信息
- [x] 错误信息对用户友好
- [x] 记录详细的错误日志
- [x] 提供错误解决建议
- [x] 支持错误码分类（E001-E008）
- [x] JMeter相关错误处理
- [x] SSH连接错误处理
- [x] nmon执行错误处理
- [x] Excel生成错误处理
- [x] 执行日志、stdout/stderr、服务端日志按配置落地

**测试用例**:
1. **JMeter错误处理测试**
   - 输入: 各种JMeter错误场景
   - 预期: 显示友好的错误信息和解决建议

2. **SSH连接错误处理测试**
   - 输入: 网络连接失败、认证失败等场景
   - 预期: 显示连接错误信息和解决建议

3. **Excel生成错误处理测试**
   - 输入: 文件权限、磁盘空间不足等场景
   - 预期: 显示生成错误信息和解决建议

### AC-006: 分布式压测（可选）
**功能描述**: 在 `distributed.enabled = true` 时验证分布式执行能力。

**验收条件**:
- [x] 能够根据配置加载 Slave 列表并握手成功
- [x] 能够按线程占比拆分负载
- [x] 能够同步启动/停止压测，输出成功率
- [x] Slave 连接失败时提供错误信息并终止执行

**测试用例**:
1. **正常分布式压测**
   - 输入: 配置 1 台或多台 Slave
   - 预期: 执行成功，统计数据完整
2. **故障场景测试**
   - 输入: 故意配置错误的 Slave 主机或凭据
   - 预期: 输出错误信息并返回非零退出码

### AC-007: CI 质量门禁
**功能描述**: 确保 CI 流水线可调用 CLI 命令并执行质量检查。

**验收条件**:
- [x] `pip install -e .[dev]` 成功完成，依赖可用
- [x] `jmeter-test-suite` 脚本可被识别并返回帮助信息
- [x] `pytest`、`ruff check`、`ruff format --check`、`mypy` 在无代码改动情况下通过
- [x] `pip-audit` 在安全依赖集合下可运行并输出结果
- [x] `jmeter-test-suite report` 在示例结果目录下成功生成报告（可通过模拟数据验证）

## 🎯 概述

本文档定义了`一键运行-单个接口.bat`批处理脚本的功能需求。该脚本旨在为Windows用户提供一键式执行JMeter性能测试和生成Excel报告的便捷入口。

### ⚠️ 平台说明

**本脚本为Windows专用**：
- 文件格式：`.bat`（Windows批处理脚本）
- 运行环境：仅Windows系统
- 部分功能（如自动打开文件夹）使用Windows专用命令

**Linux/macOS用户**：
- 可使用Python CLI命令：`python -m jmeter_test_suite all`
- 或使用对应的Shell脚本（如需要）

### 功能定位

`一键运行-单个接口.bat`是项目的Windows批处理脚本入口，主要职责是：
1. **环境准备**: 检查和准备Python运行环境
2. **依赖管理**: 自动安装和验证项目依赖
3. **配置展示**: 显示测试配置信息，帮助用户了解执行计划
4. **测试执行**: 调用Python CLI执行完整的测试流程
5. **结果展示**: 自动打开结果文件夹，便于用户查看报告

### 与其他脚本的关系

| 脚本 | 功能范围 | 关系 |
|------|----------|------|
| `一键运行-单个接口.bat` | 单个接口测试 | 调用`python -m jmeter_test_suite all` |
| `一键运行-所有接口.bat` | 所有接口批量测试 | 循环调用单个接口脚本 |

## 📋 功能需求

### FR-BS-001: Python环境检查

**功能描述**: 在执行测试前，检查Python环境是否已安装并可用

**输入**:
- 无参数输入

**处理逻辑**:
1. 尝试执行`python --version`命令
2. 检查命令执行返回码
3. 如果Python未安装或不可用，显示错误信息并提供安装建议

**输出**:
- 成功: 显示Python版本信息
- 失败: 显示错误提示，暂停等待用户操作，退出脚本

**验收标准**:
- [x] 能够检测Python是否安装
- [x] 能够显示Python版本信息
- [x] Python未安装时提供友好的错误提示
- [x] 错误时暂停等待用户操作

**相关文档**:

### FR-BS-002: 项目依赖自动安装

**功能描述**: 自动检查并安装项目所需的Python依赖包

**输入**:
- 项目的`pyproject.toml`文件

**处理逻辑**:
1. 设置`PYTHONPATH`后尝试导入`jmeter_test_suite`
2. 如果已安装，输出提示并跳转到`:deps_done`
3. 如果未安装，执行以下步骤：
   - 输出步骤提示（升级pip/安装依赖/安装项目包）
   - 升级pip工具
   - 调用`pip install -e .[dev]`
   - 如果标准源失败，切换到清华镜像重试
4. 安装完成后输出成功信息

**输出**:
- 成功: 显示"✅ Dependencies installed successfully"
- 失败: 显示错误信息，继续执行（依赖可能已部分安装）

**验收标准**:
- [x] 能够检测项目包是否已安装
- [x] 能够自动安装缺失的依赖
- [x] 支持国内镜像源（清华大学镜像）
- [x] 安装过程显示进度提示
- [x] 已安装时跳过安装步骤

### FR-BS-006: 一键执行测试

**功能描述**: 调用Python CLI执行完整的测试流程（测试执行 + 报告生成）

**输入**:
- 无命令行参数（使用配置默认值）

**处理逻辑**:
1. 执行`python -m jmeter_test_suite all`命令
2. 将命令退出码保存到`TEST_EXITCODE`
3. 若退出码为0，进入成功流程
4. 若退出码非0，尝试执行`python -m jmeter_test_suite report`进行补救
5. 根据补救结果决定进入成功或失败路径

**输出**:
- 成功: 显示"🎉 All tests completed successfully!"，并继续成功收尾
- 失败: 显示错误信息、常见问题建议，并在`pause`后退出

**错误处理**:
- Python命令执行失败
- 测试执行失败
- 报告生成失败

**常见错误场景**:
- 服务器连接问题
- 配置文件错误
- 系统资源不足
- Slave节点未启动（分布式模式）
- 网络连接问题（分布式模式）
- JMeter版本不匹配（分布式模式）

**验收标准**:
- [x] 能够正确调用all命令
- [x] 能够检测命令执行结果
- [x] 失败时提供详细的错误信息和解决建议
- [x] 错误信息对用户友好

- [功能需求](功能需求.md)

### FR-BS-007: 自动打开结果文件夹

**功能描述**: 测试完成后，自动打开文件管理器显示结果文件夹（Windows专用功能）

**适用范围**: 
- ⚠️ **Windows专用**: 此功能仅在Windows系统上有效
- 原因: 批处理脚本（`.bat`）本身是Windows专用，使用Windows的`explorer`命令

**输入**:
- 结果目录路径（默认`result`）

**处理逻辑**:
1. 调用`python -m jmeter_test_suite open-result result`
2. 若命令返回非0，调用Windows的`explorer`命令作为降级方案
3. 最终在资源管理器中显示结果文件

**输出**:
- Windows: 打开结果目录（优先走CLI逻辑，失败时使用`explorer`）
- 其他平台: `.bat`脚本不支持启动

**验收标准**:
- [x] Windows上能够正确打开结果文件夹
- [x] 文件夹路径正确
- [x] 文件可见

**跨平台说明**:
- 当前实现：Windows批处理脚本专用
- CLI命令本身支持跨平台，方便未来由其他入口复用

### FR-BS-010: 实时进度监控窗口

**功能描述**: 启动独立窗口实时追踪JMeter执行日志，便于观察进度

**输入**:
- 日志文件路径：`result/jmeter_latest.log`

**处理逻辑**:
1. 在测试前删除旧的`jmeter_latest.log`
2. 使用`start`命令运行PowerShell脚本
3. PowerShell脚本等待日志文件生成并执行`Get-Content -Wait -Tail 5`
4. 主流程结束后调用`taskkill`关闭该窗口

**输出**:
- 一个标题为“JMeter Live”的PowerShell窗口实时输出最新日志

**验收标准**:
- [x] 旧日志被清理，避免读取历史内容
- [x] 实时窗口能够在日志写入前保持等待状态
- [x] 脚本结束时自动关闭该窗口
- [x] 若窗口关闭失败，不影响主流程的退出码

### FR-BS-011: 失败补救与退出策略

**功能描述**: 在测试失败时尝试补救并规范化退出逻辑

**输入**:
- `TEST_EXITCODE`（`all`命令的原始退出码）

**处理逻辑**:
1. 当`TEST_EXITCODE`非0时执行补救流程
2. 调用`python -m jmeter_test_suite report`尝试生成报告
3. 若补救成功，视为整体成功并继续执行成功路径
4. 若补救仍失败，跳转到`failure_path`输出常见问题列表
5. 失败路径中执行`pause >nul`后，以原始退出码退出脚本

**输出**:
- 成功补救: 输出“Report generated despite monitor failure”提示
- 补救失败: 输出失败原因及常见问题列表

**验收标准**:
- [x] 精确保留原始退出码，用于最终退出
- [x] 补救成功时不会重复报错
- [x] 失败提示包含常见问题列表
- [x] 失败场景下保持窗口暂停，方便用户查看

## 🎯 使用场景

### 场景1: 首次使用

1. 用户双击`一键运行-单个接口.bat`
2. 脚本检查Python环境
3. 自动安装项目依赖
4. 显示配置信息与模式信息
5. 启动实时进度窗口并执行测试
6. 如遇失败尝试补救报告
7. 生成报告并打开结果文件夹

### 场景2: 日常使用

1. 用户双击`一键运行-单个接口.bat`
2. 脚本检测到依赖已安装，跳过安装步骤
3. 显示配置信息与模式信息
4. 启动实时进度窗口并执行测试
5. 根据退出码决定是否补救
6. 生成报告并通过CLI+explorer打开结果文件夹

### 场景3: 错误处理

1. Python未安装 → 显示错误提示，暂停等待用户
2. 依赖安装失败 → 尝试使用清华镜像源，继续执行
3. 测试执行失败 → 自动尝试报告补救，必要时输出常见问题列表并保留退出码
4. 实时进度窗口在失败后被关闭，避免残留进程
